# Trade Real Capital Readiness

本文档给出 Trade 从研究工作台走向真实资金接入前必须完成的标准流程。当前代码仍是 paper-only，本文档不是上线许可，而是闸门清单。

## 当前结论

Trade 目前适合作为研究和 paper-only 工作台。已经修正的高风险基础项包括：

- VWAP 按最新 K 线所在 session 计算，不再跨交易日累计。
- 回测成交从 `modeled_current_close` 改为 `next_bar_open`，降低前视偏差。
- Paper 买入手续费改为名义金额内扣，不再双重扣减现金。
- 多标的回测持久化每个标的的 trades、equityCurve、orderIntents、riskEvents。
- 回测 summary 增加核心仓只持有基准和 T 策略相对核心仓 alpha。
- Quick paper 订单开始使用服务端默认 RiskLimits。
- CSV 本地历史数据可通过 HTTP `dailyPath` / `intradayPath` 进入回测和 K 线接口。

这些修正只让研究结果更可审计，不代表可以接入真实资金。

## 阶段 0：策略假设审查

目标：说明策略为什么可能有边际优势。

必须回答：

- VWAP 回踩和收复是在赚短期均值回归，还是趋势延续。
- 该信号在哪些市场状态下有效：上涨、下跌、盘整、高波动、低波动。
- 该信号在哪些状态下会失效：流动性枯竭、单边下跌、财报跳空、趋势破坏。
- 核心仓 + T 仓相比纯持有的经济意义是什么。

通过标准：

- 有书面策略假设。
- 每个假设都能对应到可测试指标。
- 不能只用单段漂亮回测曲线作为理由。

## 阶段 1：真实数据基础设施

目标：停止依赖 Synthetic 调参。

必须完成：

- 接入真实、可复现的历史数据。
- 股票数据必须处理拆股、分红、停牌、异常跳价和缺失数据。
- 美股股票不应默认走 Binance spot 数据源，除非明确接入的是可交易且合法合规的代币化股票产品。
- CSV 路径必须指向经过质量检查的数据。
- 后续若接 vendor，应评估 Polygon、IEX、Alpaca、Tiingo 等适合股票的供应商。

通过标准：

- 每次回测结果记录 `source`、数据路径或供应商、数据时间范围和质量检查摘要。
- Synthetic 结果只能标记为 demo，不进入真实资金决策。

## 阶段 2：回测引擎纠偏

目标：确保回测结果不被基础建模错误污染。

已完成：

- VWAP session 重置。
- 下一根 K 线开盘成交。
- Paper 买入手续费双扣修复。
- 多标的明细审计。
- 核心仓只持有基准。

仍需补充：

- 隔夜跳空成交建模。
- 真实 bid/ask、成交量、盘口深度和滑点模型。
- 部分成交、拒单、限价单未成交。
- 现金、保证金、持仓可用数量和结算资金约束。

通过标准：

- 每个成交都有信号时间、成交时间、成交假设、手续费、滑点、风险检查。
- 每个拒绝事件都有明确原因。
- 核心仓只持有基准和策略 alpha 必须随结果持久化。

## 阶段 3：方法论审查

目标：识别过拟合。

必须完成：

- 样本内 / 样本外划分，不能只在全历史上调参。
- Walk-forward 验证。
- 参数敏感度分析：例如 `pullback_pct`、`stop_loss_pct`、`buy_grid_spacing_pct` 做 20% 到 30% 扰动。
- 成本敏感性：滑点和点差至少跑 2x、3x。
- 市场状态切片：上涨、下跌、盘整、高波动、低波动分别统计。
- Monte Carlo 或 bootstrap 重采样交易序列，给出收益和最大回撤区间。
- 交易样本量不足时，不展示胜率/盈亏比为可靠结论。

通过标准：

- 参数变化附近表现平滑，没有只在单点参数上好看。
- 样本外结果未明显崩塌。
- 成本放大后仍能解释 alpha 来源，或明确策略暂不合格。

## 阶段 4：风险框架

目标：所有路径共用同一套风控。

必须完成：

- 固定金额下单升级为波动率和 confidence 约束下的仓位模型。
- 最大加仓层数已经有默认限制，但仍需账户级最大回撤估算。
- 组合相关性和行业集中度上限。
- 单笔最大金额、T 仓上限、点差上限、行情新鲜度、日内亏损上限。
- 一键停止和一键平仓设计。
- 手工 paper、策略 paper、未来 live 下单都必须走同一 RiskLimits 或其升级版。

通过标准：

- 任何下单路径都不能绕过风控。
- 风控拒绝优先于下单。
- 风控参数和触发记录随订单审计保存。

## 阶段 5：市场规则、账户规则和合规核查

目标：确认策略执行假设在目标市场和账户类型中成立。

必须明确：

- 目标市场：A 股、美股、加密货币、代币化股票，不能混用假设。
- 账户类型：现金账户、保证金账户、券商 paper 账户。
- 结算周期、日内交易限制、未结算资金使用限制。
- 券商 API 的订单频率限制、最小报单间隔、订单类型支持。
- 税务规则，例如美股 wash sale 风险。

当前规则核查要点：

- SEC 已将美国证券标准结算周期缩短至 T+1，规则生效日为 2024-05-28。来源：[SEC press release 2023-29](https://www.sec.gov/newsroom/press-releases/2023-29)。
- FINRA Regulatory Notice 26-10 发布于 2026-04-20，新的 intraday margin standards 自 2026-06-04 生效，并允许成员到 2027-10-20 前分阶段实施；因此不能只写死旧 PDT 25,000 美元规则，必须按目标券商当前实施规则核查。来源：[FINRA Regulatory Notice 26-10](https://www.finra.org/rules-guidance/notices/26-10)。
- A 股常见股票交易存在 T+1 可卖约束；如果目标是 A 股，先买后卖的反 T 假设不能直接套用，必须按可用底仓和可卖数量建模。

通过标准：

- 每个策略实例绑定明确市场和账户类型。
- 回测和 paper 都模拟对应市场约束。
- 没有合规规则核查记录时，不能启用 live adapter。

## 阶段 6：真实行情纸面交易

目标：用真实实时行情验证模型偏差。

必须完成：

- 至少 1 到 3 个月真实行情 paper trading。
- 记录信号生成延迟、行情延迟、下单延迟。
- 比较 paper 实际成交价和回测假设成交价。
- 根据真实偏差修正滑点和点差模型。
- 记录数据源失败、断连、异常跳价和恢复行为。

通过标准：

- 实际 paper 成交与回测假设偏差可量化。
- 数据源异常不会导致错误下单。
- 策略在真实行情中没有频繁触发未预期风控。

## 阶段 7：交易基础设施

目标：具备真实订单系统最低安全能力。

必须完成：

- 幂等下单 key，防止网络重试重复下单。
- 订单状态机：pending、partially_filled、filled、rejected、cancelled、expired。
- 券商回报处理和本地台账 reconciliation。
- 用户、权限、token、审计日志。
- 凭证管理，sandbox 和 production 严格隔离。
- 告警：风控触发、连续亏损、数据源失败、订单失败、仓位不一致。

通过标准：

- 每笔真实资金相关操作能复盘：谁、何时、什么参数、什么版本、什么结果。
- 本地仓位和券商仓位可对账。
- 任何失败都能进入安全状态，而不是重复下单。

## 阶段 8：分阶段真实资金投放

目标：用极小资金验证链路，再逐步爬坡。

步骤：

1. 沙盒 live adapter 验证。
2. 极小真实资金冒烟测试。
3. 观察实际成交、拒单、滑点和账户更新。
4. 设置暂停标准：实际回撤超过回测最大回撤 1.5 倍、连续亏损超过历史 95 分位、数据源异常、仓位对账失败。
5. 每次提高资金前重新评估回测、paper 和真实表现偏差。

通过标准：

- 资金爬坡不是时间驱动，而是证据驱动。
- 暂停和降级规则由系统自动触发，并有人类复核。

## 阶段 9：持续治理

目标：避免策略上线后失控或衰减无人发现。

必须完成：

- 任何参数或代码改动重新跑回测、样本外、paper 验证。
- 策略版本、参数版本、数据版本、风控版本全部留档。
- 定期监控近期胜率、盈亏比、滑点、成交率、风险拒绝率是否偏离历史。
- 定期复查市场结构变化和监管规则变化。

通过标准：

- 没有未经验证的参数热更新。
- 有明确策略退役标准。

## 当前禁止事项

- 禁止接真实券商订单接口。
- 禁止在 UI 中出现“实盘已连接”或“自动交易已启动”。
- 禁止用 Synthetic 回测结果作为真实资金依据。
- 禁止绕过 RiskLimits 手工下单。
- 禁止没有幂等 key 的真实下单。

Trade 下一阶段应优先补样本外验证、真实数据质量检查、隔夜跳空和订单状态机，而不是先接 live broker。
